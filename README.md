# Go1 — задание T2 (блок безопасности)

Решение задания T2. Это узел на ROS 2, который стоит между командами и роботом.
Он берет команды из `/lowcmd_bare`, проверяет их и отправляет дальше в `/lowcmd`
только то, что безопасно.

## Как работает

Узел 200 раз в секунду отправляет команду в `/lowcmd`. Каждая новая команда проверяется:

1. Если в команде есть NaN или Inf (хоть где-то), она выкидывается целиком,
   а на выходе остается прошлая нормальная команда.
2. Если `mode` не равен 10, команда тоже выкидывается.
3. Если угол сустава за пределом, он ставится на предел. Если число вообще не похоже на угол
   (больше 50 рад, например 2.146e9), команда выкидывается.
4. kp, kd, tau и dq обрезаются до разрешенных значений: kp от 0 до 1000, kd от 0 до 100,
   tau от -100 до 100, dq от -20 до 20.
5. Проверяется, не врежется ли робот сам в себя в этой позе. Для этого используется MuJoCo,
   модель робота и список из 655 пар деталей.
   Если детали входят друг в друга больше чем на 1 мм, команда выкидывается.

Выход двигается к новой цели не сразу, а шагами, максимум 5 градусов
за раз, как в ТЗ. Каждый шаг тоже проверяется на столкновения, через каждые 0.1 градуса.
Если на пути будет столкновение, робот останавливается перед ним.

Если цель прыгнула сразу больше чем на 5 градусов, это считается подозрительным, и выход
идет к ней медленнее, по 0.5 градуса за раз. Пока он идет, dq и tau из этой команды не передаются.

Если команды не приходят 0.2 секунды, включается удержание:
держится последняя нормальная поза, dq = 0, tau = 0, kp и kd берутся из последней команды.
Через 0.4 секунды поза точно стоит на месте (по ТЗ надо успеть за 0.5).

## Файлы

- `safety/safety.py` — вся логика проверок
- `safety/collision.py` — проверка столкновений в MuJoCo
- `safety/safety_node.py` — сам ROS 2 узел
- `safety/pairs.csv` — список пар деталей от организаторов
- `entrypoint.sh` — запуск контейнера (`ping` или `T2`)
- `Dockerfile` — сборка образа

## Сборка образа

```bash
docker build --platform linux/amd64 -t go1-t2:dev .
```
