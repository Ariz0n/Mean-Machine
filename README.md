# Go1 — задания T4 (оценка движения) и T5 (навигация и ArUco)

Один образ на оба задания. Режим выбирается аргументом: `/entrypoint.sh ping`, `T4` или `T5`.

# T4 — оценка движения робота

Решение задания T4. Это узел на ROS 2, который оценивает, где находится робот и куда он повернут.
Он берет данные из `/imu/data` и `/scan` и отправляет оценку в `/odom` и в TF `odom → trunk`.
Роботом узел не управляет, в `/cmd_vel` ничего не публикует.

## Файлы

- `odom/odom.py` — вся логика одометрии
- `odom/icp.py` — карта и наложение скана на карту
- `odom/odom_node.py` — сам ROS 2 узел

# T5 — автономная навигация и ArUco

Решение задания T5. Робот сам едет к цели по неизвестной трассе, обходит препятствия
и распознает ArUco-метки. Карты заранее нет: она строится по лидару прямо во время движения.
Навигация сделана на Nav2: Action-сервер `/navigate_to_pose` принимает цель от Judge,
Nav2 строит путь и отправляет команды в `/cmd_vel`.

## Что запускается

`nav/t5.launch.py` запускает:

- узел одометрии из T4 (`odom/odom_node.py`): `/odom` и TF `odom → trunk`, плюс точки скана для карт Nav2;
- `nav/map_odom.py`: TF `map → odom`;
- Nav2: `bt_navigator`, `planner_server`, `controller_server`, `behavior_server`, `lifecycle_manager`;
- `nav/aruco_node.py`: распознавание меток, `/aruco/detections`.

## Файлы

- `nav/t5.launch.py` — запуск T5
- `nav/nav2_params.yaml` — настройки Nav2
- `nav/navigate.xml` — дерево поведения Nav2
- `nav/map_odom.py` — TF `map → odom`
- `nav/aruco_node.py` — распознавание ArUco

# Общее

- `entrypoint.sh` — запуск контейнера (`ping`, `T4` или `T5`)
- `Dockerfile` — сборка образа

Узлы работают до конца испытания. Если запуск завершился, `entrypoint.sh` запускает его снова
через 1 с. В T5 узлы одометрии и ArUco к тому же сами перезапускаются через 1 с, если упали;
при перезапуске одометрии `map_odom.py` сохраняет положение робота на карте.
При остановке контейнера (SIGTERM) узлы останавливаются и контейнер завершается.

## Сборка образа

```bash
docker build --platform linux/amd64 -t go1-sol:dev .
```
